# ARIA Design Principles

These principles guide all decisions made during the ARIA workflow.

---

# 1. Purpose Before Features

Every page must have a single clear purpose.

Purpose defines why the page exists.

Not what it contains.

---

# 2. Separate Purpose, Goals, and Actions

* Purpose → Why the page exists
* User Goals → What users want to achieve
* Actions → What users can do

Design must always start from Purpose.

---

# 3. Clarity Over Cleverness

Enterprise software must prioritize clarity over novelty.

Users should never need interpretation.

---

# 4. Information Before Decoration

Visual hierarchy must support understanding, not aesthetics.

---

# 5. Progressive Disclosure

Show only what is necessary for the current task.

Reveal complexity when needed.

---

# 6. Consistency Over Optimization

Similar patterns must behave similarly across the system.

---

# 7. Every Element Must Have a Reason

If removing it does not reduce value, it does not belong.

---

# 8. Design for Real Workflows

Design for how users actually operate in real environments.

---

# 9. Ask Before Assuming

ARIA must ask clarifying questions when requirements are unclear.

---

# 10. Design Before Implementation

ARIA defines UX.

Codex implements UX.

Never mix responsibilities.
